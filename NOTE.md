# Restaurant Ordering System - Project Folder Structure & Architecture

This document provides a guide to the project directory structure, explaining the responsibility and purpose of each directory and file in the frontend architecture.

---

## 📁 Root Directory Overview

```text
resturant_ordering_system/
├── public/                 # Static assets served as-is (e.g. favicon)
├── src/                    # Main application source code
├── dist/                   # Production build output (generated by `npm run build`)
├── node_modules/           # Installed NPM dependencies
├── index.html              # Single Page Application HTML entry file
├── package.json            # Project dependencies, scripts, and metadata
├── vite.config.js          # Vite build tool and plugin configuration
├── NOTE.md                 # Project architecture & folder guide (this file)
└── README.md               # Quick start and general project info
```

---

## 📂 `src/` Directory Breakdown

```text
src/
├── assets/                 # Static media and global styling assets
├── components/             # Reusable UI & presentation components
│   ├── base/               # Basic primitives (Buttons, Inputs, Badges, Modals)
│   ├── layout/             # Layout fragments (Navbar, Sidebar, Footer)
│   └── ui/                 # Design system compound widgets (Cards, Tables, Drawers)
├── composables/            # Reusable Vue composition functions / hooks
├── layouts/                # High-level page layout templates
├── modules/                # Domain/feature-specific business modules
├── pages/                  # Route views (page-level components)
│   ├── auth/               # Login, Register, Password Reset
│   ├── dashboard/          # Admin & Kitchen/Staff management views
│   ├── home/               # Customer landing & welcome page
│   └── preview/            # Menu browsing & order preview
├── router/                 # Vue Router routing definitions & guards
├── services/               # HTTP client & backend API communication layers
├── stores/                 # Global state management (Pinia stores)
├── App.vue                 # Top-level root component
├── main.js                 # Application entry point
└── style.css               # Global stylesheet & Tailwind CSS entry
```

## 🔍 Detailed Explanations of Directories

### 1. `src/assets/`
* **Purpose**: Houses images, SVGs, custom icons, fonts, and static resources used across the UI.
* **Examples**: `hero.png`, restaurant logos, food category icons.

### 2. `src/components/`
* **Purpose**: Holds modular, reusable Vue components. Divided into three clear layers:
  * **`base/`**: Atomic, dumb components with no business logic (e.g., `BaseButton.vue`, `BaseInput.vue`, `BaseModal.vue`).
  * **`layout/`**: Structural components reused inside layouts (e.g., `AppNavbar.vue`, `AppSidebar.vue`, `Footer.vue`).
  * **`ui/`**: Compound UI patterns (e.g., `FoodCard.vue`, `OrderSummaryCard.vue`, `StatusBadge.vue`).

### 3. `src/composables/`
* **Purpose**: Reusable stateful logic using Vue 3 Composition API (`use*` functions).
* **Examples**:
  * `useAuth.js`: Login state, tokens, user permissions.
  * `useCart.js`: Adding/removing items, calculating order total and taxes.
  * `useNotification.js`: Toast alerts for order statuses.

### 4. `src/layouts/`
* **Purpose**: Wrappers that provide consistent page frames (headers, sidebars, navigation) around `<slot />` or nested `<router-view />`.
* **Examples**:
  * `CustomerLayout.vue`: Clean customer-facing layout with top menu navigation.
  * `AdminLayout.vue`: Dashboard layout with sidebar navigation and admin metrics.
  * `AuthLayout.vue`: Centered minimal layout for login/register forms.

### 5. `src/modules/`
* **Purpose**: Grouping code by business domain (Feature-Sliced approach) if components, types, or helpers belong strictly to one business domain.
* **Examples**:
  * `modules/orders/`: Order status tracking, receipt generator.
  * `modules/menu/`: Dish filtering, modifier/topping selections.
  * `modules/table/`: QR table selection and seating status.

### 6. `src/pages/`
* **Purpose**: Page-level components mapped directly to URLs in the router.
  * **`auth/`**: `LoginPage.vue`, `RegisterPage.vue`.
  * **`dashboard/`**: `DashboardHome.vue`, `OrdersManager.vue`, `MenuEditor.vue`.
  * **`home/`**: `HomePage.vue` (landing, table greeting, quick menu link).
  * **`preview/`**: `PreviewPage.vue` (item preview, quick-order modal).

### 7. `src/router/`
* **Purpose**: Configuration for client-side page routing using `vue-router`.
* **Key file**: `index.js` defines route paths, lazy-loaded page components, and navigation guards (e.g., redirecting unauthenticated users from `/dashboard`).

### 8. `src/services/`
* **Purpose**: Centralized communication with your backend REST API.
* **Examples**:
  * `api.js`: Base Axios or Fetch instance with baseUrl, headers, and interceptors for auth tokens.
  * `menuService.js`: Methods like `getMenuItems()`, `getMenuCategory()`.
  * `orderService.js`: Methods like `placeOrder()`, `getOrderHistory()`.

### 9. `src/stores/`
* **Purpose**: Global application state using Pinia.
* **Examples**:
  * `authStore.js`: Current logged-in user profile and auth token.
  * `cartStore.js`: Items currently in the customer's cart, quantity counters, and pricing calculations.

### 10. `src/App.vue` & `src/main.js`
* **`App.vue`**: Root component of Vue. Renders global notifications/modals and the active page through `<router-view />`.
* **`main.js`**: Initializes the Vue app, registers plugins (Vue Router, Pinia), imports global CSS, and mounts the application to `#app` in `index.html`.

## 🛠️ Recommended Workflow for Adding New Features

1. **New Page/Route**:
   1. Create `src/pages/[feature]/[PageName].vue`.
   2. Register the route in `src/router/index.js`.
2. **Backend API Call**:
   1. Add API request functions in `src/services/[feature]Service.js`.
3. **Shared State (e.g., Cart)**:
   1. Create a Pinia store in `src/stores/[feature]Store.js`.
4. **Reusable UI Elements**:
   1. Create reusable buttons/cards in `src/components/`.
